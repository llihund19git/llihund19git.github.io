Case study 02 · Mobile and cloud delivery

Roadr

End-to-end work across a React Native application, Node.js APIs, MongoDB, location services, WebSocket chat, notifications, AWS, and manual test releases.

Role
Full-Stack Developer
Employer
Creative Interlace Technologies OPC
Period
Began approximately in 2022
Team
2 full-stack developers

Context and ownership

Two developers across the stack.

Roadr enabled vehicle owners to request roadside services such as repair assistance, towing, and emergency fuel delivery.

I worked in a two-person full-stack team. My scope included mobile screens, maps and geolocation, notifications, backend work, AWS-supported deployment, and broader end-to-end delivery.

Delivery-stage boundary

During my involvement, builds were being evaluated by stakeholders and externally engaged QA through Google Play testing and Apple TestFlight. The application became public after I had left the project, so I do not attribute the later release or post-employment results to my work.

Engineering scope

Useful real-time behavior without overstating it.

The application included WebSocket-based real-time chat and location distance and estimated-time functionality.

The confirmed scope does not include complete real-time location tracking, so this case study deliberately avoids that claim. Authentication, authorization, validation, and secure API/database access were part of the application work.

  1. 01
    Location-aware experience

    Implemented maps and geolocation work, including distance and estimated-time information.

  2. 02
    Realtime messaging

    Used AWS API Gateway WebSocket APIs for chat functionality.

  3. 03
    Manual release path

    Prepared and uploaded test builds manually; no CI/CD pipeline was used during my involvement.

Challenge

Learning unfamiliar AWS services.

The hardest part was cloud-service configuration and usage rather than application-code implementation. I used official documentation, hands-on testing, and explanatory materials to understand and verify the integrations.

Quality

Validate before stakeholder review.

Application and API behavior was tested manually before stakeholder evaluation and externally engaged QA. Test builds were distributed through Google Play testing and TestFlight.

What I would improve

Automate the release process.

I would add CI/CD to replace manual test-build uploads and make delivery more repeatable, visible, and less dependent on individual steps.
