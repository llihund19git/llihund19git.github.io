Case study 01 · Production business system

Official Alumni

Backend feature delivery, AWS-supported releases, and a multilingual search investigation for an existing Laravel platform under continuous development.

Role
Back-End Developer
Employer
Hackazouk, Inc. (PH)
Period
Dec 2023–Dec 2025
Team
7 developers

Context and responsibility

Strengthening an existing platform.

The platform already existed when I joined. My work focused on continuous backend development: APIs, database models, notifications, staging and production deployments, and features such as scheduled chat messages and stickers.

I worked within a seven-developer team: three backend developers, including one senior developer, two web frontend developers, and two mobile developers. Across the engagement, I delivered approximately ten general product features, plus refactoring, defect resolution, and unit-testing work.

Key engineering problem

Multilingual search without unacceptable latency.

Search needed to handle alphabetic A–Z, Hiragana, Katakana, and Kanji content while keeping database-query performance practical.

  1. 01
    Compared approaches

    Evaluated and tested MySQL full-text search and AWS Elasticsearch, recording results rather than choosing by preference alone.

  2. 02
    Iterated over several months

    Repeated testing was used to balance useful matching with query latency across different characters and terms.

  3. 03
    Selected MySQL full-text search

    The production implementation used MySQL full-text search. Some very common characters or words were excluded because including them made searches excessively slow.

Quality and security

Release with verification.

Work included validation, authentication and authorization, secure database queries, sensitive-data handling, caching, and query optimization. Verification used PHPUnit, Postman, QA/UAT, and code review.

Operations

Support the delivery path.

I used the existing CI/CD pipeline for staging and production releases, checked CloudWatch logs during investigations, and monitored whether automated updates completed successfully. I do not claim ownership of the original pipeline setup.

Reflection

Design for performance earlier.

The search work changed how I approach new features: I now consider likely database-query impact during design and implementation instead of waiting for a slowdown to appear.
