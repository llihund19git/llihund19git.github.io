Case study 03 · End-to-end ownership

DCSC Malolos

A membership and event-management platform connecting registration, payment tracking, QR attendance, statistics, and reporting for a diocesan communications community.

Role
Full-Stack Developer
Engagement
Independent project
Period
Mar 2025–Present
Scale
Approx. 2,000 members; 1,000+ active

Problem and ownership

One connected event workflow.

The Diocesan Commission on Social Communications needed a clearer way to maintain member information and administer events.

As the sole developer, I handle requirements, the responsive interface, Laravel workflows, database design, hosting, deployment, ongoing support, and feature development when needed. Other participants support the work as testers.

Privacy boundary

No member information, private account data, QR codes, payment receipts, or identifiable attendance records are shown in this case study. The screenshot is limited to an approved public event page.

Architecture

A focused full-stack system.

The application connects member approval and event operations through one relational workflow.

Core workflow

Registration to verified attendance.

  1. 01
    Membership approval

    A parish coordinator verifies that a registrant belongs to the parish before membership approval.

  2. 02
    Event registration and payment record

    The system records registration and payment status. It displays payment QR or bank details and accepts an uploaded receipt; it does not process online payments through a gateway.

  3. 03
    Unique member QR

    Each approved user has a unique QR code on the dashboard. An administrator assigns authorized scanner users for each event.

  4. 04
    Attendance validation

    A scan checks event registration and payment status before attendance is recorded. Invalid, incorrect, or unregistered codes return an error.

  5. 05
    Connected reporting

    Event registration, payments, attendance, statistics, and reports share a connected data model—the hardest implementation problem in the project.

Quality and security

Review every workflow.

Authentication and authorization protect the application. Testing is primarily manual. AI-assisted PHPUnit tests were introduced in 2026, and I review and validate the permitted generated tests rather than treating AI output as automatically correct.

Release and support

Practical manual delivery.

Deployment currently uses a manual Git pull in cPanel followed by required database migrations. Support and feature updates are provided when needed; no formal automated monitoring, logging, or backup workflow has been confirmed.

What I would improve

Build the next delivery layer.

My next priorities would be CI/CD, broader automated-test coverage, and a mobile version—improving repeatability and reach without changing the verified current state.
